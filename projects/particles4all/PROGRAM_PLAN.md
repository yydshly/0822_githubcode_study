# Particles4All 总体研究与扩展计划

## 1. 计划性质

本文件是项目的执行控制文件。后续工作不由临时对话决定，而由宏观目标、模块依赖、工作包状态和阶段 Gate 驱动。

- [`RESEARCH_CHARTER.md`](RESEARCH_CHARTER.md) 规定研究边界和成果分类；
- 本文件规定整体目标、模块、阶段、依赖和执行顺序；
- [`program-state.json`](program-state.json) 记录机器可读的当前状态；
- 各实验规格只属于某个工作包，不能反向改变总体目标。

## 2. G0｜宏观目标

系统研究 Particles4All 的原始能力、实现原理和工程边界，基于其真实 WebGPU/PBF/Shape Matching 能力建立可控制、可扩展、可验证的局部液体—刚体运行时，并判断：

1. 哪些能力可以直接复用；
2. 哪些能力需要运行接口、输入、边界、碰撞或渲染扩展；
3. 扩展后适合哪些局部交互场景；
4. 性能、兼容性、真实性和维护成本是否支持长期沉淀；
5. 最终应保持研究样例、形成可复用组件、贡献上游，还是停止投入。

最终产物不是“若干水效果页面”，而是一项有证据的技术决策：

```text
KEEP AS RESEARCH
或 PACKAGE AS RUNTIME
或 CONTRIBUTE UPSTREAM
或 STOP
```

## 3. 目标架构

```text
M0 研究治理与范围
        ↓
M1 原库能力与原理
        ↓
M2 可控运行与证据基础设施
        ↓
M3 输入、事件与交互扩展
        ↓
M4 边界、碰撞与场景构造扩展（条件模块）
        ↓
M5 场景验证矩阵
        ↓
M6 工程化与长期价值决策
```

场景只消费前面模块的能力。任何场景不得绕过 M1–M4 自行实现另一套流体算法。

## 4. 模块定义

### M0｜研究治理与范围

目标：确保研究始终围绕 Particles4All，不扩散成通用水环境研发。

产物：固定上游版本、许可边界、U0/U1/E1/S1/C0 分类、停止扩散规则、Water Scene Lab 冻结记录。

完成标准：所有活动工作包都能映射到原库源码、扩展点和证据 Gate。

状态：`completed`

### M1｜原库能力与原理

目标：建立原库的模拟、刚体、GPU 数据、表面渲染、交互和性能能力地图。

子模块：

- M1.1 PBF 密度约束、XSPH、表面张力；
- M1.2 Shape Matching 刚体及刚液统一邻域；
- M1.3 均匀网格、scan、scatter 与 GPU buffer；
- M1.4 particle、mesh、ray march、SSFR 渲染链；
- M1.5 参数、设备限制和真实性边界。

产物：源码索引、固定上游运行证据、受控能力 A/B、性能基线。

状态：`completed-baseline`，后续扩展发现新问题时增量更新。

### M2｜可控运行与证据基础设施

目标：在不改变原库物理结果的前提下，建立确定性步进、冻结采样和 GPU 完成点。

子模块：

- M2.1 Runtime Adapter；
- M2.2 `reset / step / sample / flush / dispose` 契约；
- M2.3 原页面与 Adapter 等价回归；
- M2.4 浏览器、控制台、数值和视觉证据产物。

完成证据：契约测试 14/14、Intel Gen-12LP WebGPU 等价检查 34/34。

状态：`completed`

### M3｜输入、事件与交互扩展

目标：让外部场景可以通过明确接口向原求解器输入液体和事件，而不是操作页面控件或依赖墙钟。

工作包：

| 工作包 | 目标 | 依赖 | Gate | 状态 |
| --- | --- | --- | --- | --- |
| M3-WP1 | Adapter 暴露受控 `injectFluid()`，直接调用原库 `Sim.appendFluid()` | M2 | 固定输入计数、容量、非有限值和重置一致 | `completed` |
| M3-WP2 | 建立整数 tick 事件队列，调度注入、施力和采样 | M3-WP1 | 事件顺序、tick、重放和结果稳定 | `completed` |
| M3-WP3 | 建立流体包生成器，按 spacing 生成可复用格点输入 | M3-WP1 | 无重叠失稳、输入数量精确、配置可序列化 | `completed` |
| M3-WP4 | 抽象刚体初态与可观测交互事件 | M3-WP2、M3-WP3 | 刚体身份、初态、响应和采样可追踪 | `completed` |

模块完成标准：同一配置可以 Reset 后按整数 tick 重放输入和交互，并得到容差内一致的聚合结果。

### M4｜边界、碰撞与场景构造扩展

目标：只有当 M3 场景暴露真实限制时，才扩展箱体边界或基础刚体形状。

候选工作包：局部开口/闸门、静态复杂边界、任意碰撞体可行性、资源释放。每项必须先证明原 box/sphere/torus 能力不足。

状态：`conditional / closed`。M4-WP1 已完成：开放出口确有缺口，但 M5-S2 已复用内部 box 刚体验证价值；M4-WP2 因容器与复杂碰撞 fork 成本过高，在最终决策中取消。

### M5｜场景验证矩阵

目标：用少量、差异明确的局部场景验证模块复用和真实价值。

| 场景工作包 | 验证目标 | 消费模块 | 状态 |
| --- | --- | --- | --- |
| M5-S1 落水池局部冲击 | PBF 液体包与 Shape Matching 刚体双向作用 | M2、M3 | `completed` |
| M5-S2 闸门/喷流 | 受控输入与内部 box 闸门能否复用 M3 能力 | M2、M3、M4-WP1 | `completed` |
| M5-S3 容器倾倒/溢流 | 审计中空容器、姿态与渲染扩展成本 | M2、M3、条件 M4 | `completed / STOP` |

Ocean、River、Watershed 和宏观 Flood 不在本项目场景矩阵内。

### M6｜工程化与长期价值

目标：把研究结果转化为继续、包装、上游贡献或停止的最终决定。

评价维度：

- 能力覆盖：局部自由液面、刚体作用、输入、边界和渲染；
- 性能：粒子数、substeps、iterations、GPU sim/render 时间；
- 兼容性：Chrome/Edge/Safari、Intel/NVIDIA/Apple、storage buffer 限制；
- 集成成本：API、资源生命周期、场景配置、调试和测试；
- 产品价值：是否产生普通 shader/装饰粒子难以替代的交互收益；
- 维护价值：本地 fork 成本与上游贡献可能性。

状态：`completed`。M6-WP1 已完成 Chrome/Edge × Intel Gen-12LP 的有界性能与生命周期基线；M6-WP2 已区分内部组件与上游候选；M6-WP3 已形成最终组合决策。

## 5. 阶段 Gate

| Gate | 判断 | 状态 |
| --- | --- | --- |
| G1 原库真实性 | 是否存在并运行真实 PBF、刚体与 WebGPU 链 | `passed` |
| G2 运行控制等价 | Adapter 是否保持原求解结果 | `passed` |
| G3 受控输入 | 外部液体输入是否精确、稳定、可重置 | `passed` |
| G4 局部交互 | PBF 与刚体响应是否形成有价值、可重复差异 | `passed` |
| G5 模块复用 | 同一输入/事件/边界模块能否支撑至少两个场景 | `passed` |
| G6 长期价值 | 是否值得组件化、fork、上游贡献或停止 | `passed` |

Gate 未通过时，不允许通过增加场景装饰来绕过。

## 6. 执行规则

1. 任意时刻只能有一个 `active` 工作包。
2. 活动工作包必须属于当前 `active` 模块，且依赖全部完成。
3. 每个工作包固定包含：输入、原库映射、修改点、测试、证据、结论和状态迁移。
4. 工作包通过后自动推进到计划中的下一依赖项；失败则执行修复、降级或停止规则。
5. 普通实现细节由计划驱动推进，不再逐项请求“继续”。
6. 只有以下情况需要用户决策：改变 G0、引入新技术主线、扩大到宏观水环境、接受重大兼容/性能代价、发布或破坏性操作。

```text
项目状态：completed
最终决策：KEEP AS RESEARCH + PACKAGE INTERNAL TOOLKIT
上游候选：修正慢帧 FPS 墙钟统计（本地 patch 已准备，未外部提交）
停止路线：复杂碰撞/容器 fork、宏观水环境、通用实时 SDK
```

## 8. 汇报格式

每轮执行只汇报四件事：

1. 完成了哪个工作包；
2. Gate 证据与失败项；
3. 项目状态发生了什么变化；
4. 下一个自动进入的工作包。

不再用发散式场景讨论替代项目状态。
