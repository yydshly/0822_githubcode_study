## 最终判断

Particles4All 的有效价值不是通用“水场景生成”，而是一个运行在浏览器 WebGPU 上的**局部液体—刚体统一粒子物理内核**。它最适合有限空间内、需要水与物体真实相互作用的效果：容器注水、倾倒与溢流、喷流、局部落水冲击、浮沉、漂浮物和可交互障碍。

本阶段已经完成源库能力核验、受控 A/B、运行适配、三个局部扩展切片、性能边界和长期价值判断。现保留代码、网页与证据，停止继续扩张场景。

## 已证实的源库能力

| 能力 | 源库实现 | 可见效果 |
| --- | --- | --- |
| 局部自由液面 | Position Based Fluids、密度约束、XSPH、表面张力 | 水体堆积、流动、聚散和液团趋势 |
| 液体—刚体耦合 | 流体与刚体粒子共享邻域和约束过程 | 排水、浮沉、冲击和姿态变化 |
| 刚体保持 | Shape Matching | 刚体粒子受水作用但保持整体形状 |
| 边界与交互 | 箱体边界、倒水、推水、拖动物体 | 容器内注水和局部互动 |
| 表面显示 | particles、mesh、ray march、SSFR | 从诊断粒子到连续水面表现 |
| GPU 执行与诊断 | WebGPU 网格邻域、扫描、计时和 verify | 浏览器端高并行模拟与可验证运行 |

## 最适合直接使用的场景

1. 有限容器中的注水、倾倒、溢流和液体晃动。
2. 水枪、喷口、闸门等短距离喷流与局部冲击。
3. 漂浮物、浮具、障碍物和简单机关的水体互动。
4. 游戏、互动展览和教学中的局部液体物理镜头。
5. 需要同屏展示 particles / mesh / SSFR 差异的算法研究与调参工具。

## 可以混合接入，但不是完整场景求解器

| 宏观场景 | 合理用法 | 不应承诺 |
| --- | --- | --- |
| 瀑布 | 落水池、石块冲击、近景水团和刚体响应 | 完整连续水幕、白沫与雾的真实模拟 |
| 河流 | 闸门、桥墩、漂浮物、船体附近的局部交互 | 长河流量传播、河床冲刷和水文精度 |
| 海洋 | 岸边、船体接触区或局部破碎浪的近场补充 | 大尺度波谱、无限海面和完整海况 |
| 洪水/流域 | 小范围障碍交互的视觉模块 | 洪水演进、风险判断或工程计算 |

宏观水面应由波谱、浅水、高度场或专业求解器负责；只有近场液体—刚体互动交给 Particles4All。二者需要明确的数据接口和真实性标签。

## 明确停止的方向

- 不独立重做海洋、河流、流域或洪水求解器。
- 不把运动学粒子、Three.js 水面或故事包装计入源库能力。
- 不宣称工程 CFD、水文、防洪、流量或承载精度。
- 不在缺少任意碰撞体前继续复杂中空容器产品化。
- 不把当前 Adapter 描述为稳定 npm SDK。

## 性能边界

Intel Gen-12LP 实测中，约 28K 粒子的 SSFR 只能作为演示档；100K 与 300K 已不具备实用实时帧率。实际产品必须按目标 GPU、粒子数、求解子步、约束迭代和渲染分辨率重新建立预算，不能从本机结果外推跨设备性能。

## 重新启动条件

只有出现明确使用场景时才重新打开，并至少满足以下一项：

1. 产品确实需要局部、双向的液体—刚体交互，而普通视觉水面无法满足。
2. 已知目标设备和帧率预算，可以定义粒子数与质量档位。
3. 需要把已验证 Adapter 接入具体游戏、展览、教学或工业可视化原型。
4. 上游补齐稳定运行接口、资源释放或复杂碰撞体能力，值得重新评估。
5. 预期场景价值足以承担求解器、渲染、资产和跨设备测试成本。

重启时先写一页“场景问题—必须能力—验收画面—性能预算”，再从现有实验台选择最接近的源库能力做单变量验证，不再从宏观水场景自由扩散。
