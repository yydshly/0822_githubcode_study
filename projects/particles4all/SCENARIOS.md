# 场景驱动扩展说明

## 核心方法

演示不再按 PBF、浮力、SSFR、100K 等技术名平铺，而按下面的因果链组织：

```text
使用问题 → 受控差异 → 重点观察 → 关联能力 → 技术透视 → 判断边界
```

每个 A/B 对照尽量只改变一个声明变量，并保持初始流体、相机、注水规格、质量档位和采样规则一致。当前页面使用单 WebGPU 视窗自动顺序运行 A → B，并精确封顶整数 solver steps；它不是两个实时实例，也还不是支持中间事件调度的引擎级 `step(n)` 重播系统。

## 当前自动受控协议

点击“运行 A → B 完整对照”后，实验台会执行同一套步骤：

1. 为 A 重新加载干净的引擎页面，暂停后清空时间余量并 Reset。
2. 在 solver step 0 前应用唯一边界变量；需要来水的场景写入精确粒子预算。
3. 外层临时包装当前实例的 `sim.step()`，精确封顶目标 solver steps；运行期间锁定 iframe 指针输入。
4. 在终点冻结并读取一次粒子、区域和刚体快照。
5. 为 B 重新加载同一引擎、相机与质量档，重复相同协议。
6. 检查 A/B 实际步数、流体粒子数与目标注入量，再生成 A、B、Δ 结果。
7. 恢复 B 供自由探索；此后任何手动操作都会把结果标记为“历史冻结采样”。

采用顺序运行是有意的：两个独立 iframe 会创建两个 GPU Device，既增加资源竞争，也不能保证两个 `requestAnimationFrame` 真正同步。当前五个场景目标分别为 180 / 144 / 162 / 144 / 144 solver steps。完整定义、结构化结果和不保证项见 [`PROTOCOL.md`](PROTOCOL.md)。

## 当前代理指标

| 场景 | 已展示的求解器内部代理 | 解释边界 |
| --- | --- | --- |
| 浮具与载荷 | 刚体中心 Y、刚体位移、流体 P95 高度、最大速度 | `u`/`u/s` 为 solver units，不是承载或吃水标定 |
| 可变容积水箱 | 实际 X 边界、流体 P95、两半区 P95 差、最大速度、刚体位移 | 整体箱壁缩放，不代表局部闸门或结构压力 |
| 液柱与成滴 | 流体 P95、垂向扩散、最大速度、固定注入粒子数 | 只能观察聚集趋势，不是 N/m 表面张力测量 |
| 互动清障 | 流体 P95、来水侧占比、两半区 P95 差、刚体位移、固定输入 | 无出口与截面探针，不声称工程流量 |
| 治水科普代理 | 实际 X 边界、积水 P95、来水侧占比、两半区 P95 差、刚体位移 | 无河道、出流、洪水风险或水利结论 |

P95 来自冻结时刻的流体粒子高度分布，目的是降低少量飞溅粒子对 `maxY` 的干扰。“来水侧/远侧”以实际 `boxX / 2` 分区，计数之和必须等于总流体粒子数；占比不是流量。最大速度沿用上游全局统计，混合流体与刚体；所有数值只适合同一固定求解器内的相对比较。

## 信息分层

### 第一层：使用场景

用户先选择要判断的问题，例如浮具承载、可变容积水箱、液柱成滴或互动清障。

### 第二层：能力关联

场景结果再关联到底层能力：PBF 流体约束、刚液双向耦合、Shape Matching、密度、动态箱体边界、连续来水和表面张力。

### 第三层：研究与诊断

`particles`、`mesh`、`ssfr` 是同一物理结果的证据视图；100K 是设备与质量档位。它们不再冒充应用场景。

## 当前场景矩阵

| 使用场景 | 受控差异 | 重点观察 | 关联能力 | 支持状态 |
| --- | --- | --- | --- | --- |
| 水上救援：浮具与载荷 | 同体积球体仅改变密度 0.22× / 2.20× | 上浮/下沉方向、垂向速度、吃水趋势 | 密度与排水、Shape Matching、刚液耦合 | ✅ 原生定性支持 |
| 可变容积水箱 | 整体 X 边界 1.00× / 0.60× | 水位、扰动、物体位移与重排 | 动态箱体边界、PBF、刚液耦合 | ✅ 原生支持 |
| 喷注实验：液柱与成滴 | 相同低重力和喷口，仅改变张力 0 / 2.1 | 液柱断裂、液团数量、聚合连续性 | 连续来水、表面张力、PBF | ✅ 原生定性支持 |
| 互动清障：水与漂浮物 | 相同来水，有/无基础刚体 | 水流路径、水面扰动、刚体位移与转动 | 统一耦合、Shape Matching、拖拽 | ✅ 原生支持 |
| 治水科普：堵与疏概念 | 封闭箱体宽域 / 整体收窄 | 积水高度趋势、漂浮物位移、稳定过程 | 来水、动态边界、刚液耦合 | △ 叙事代理，非真实河道 |

## 同一能力如何形成场景差异

| 能力 | 场景 A 的侧重点 | 场景 B 的侧重点 |
| --- | --- | --- |
| 动态箱体边界 | 水箱：容积变化与水位响应 | 治水代理：空间收窄的叙事反馈 |
| 刚液双向耦合 | 浮具：载荷与浮沉 | 清障：拖动物体后水体反作用 |
| 连续来水 | 喷注：液柱断裂与成滴 | 清障：来水遇到障碍后的路径变化 |
| SSFR | 应用层：连续水面可读性 | 诊断层：法线、深度和厚度来源 |

这类横向扩展的价值不在于复制更多页面，而在于让同一能力围绕不同用户问题产生不同观察重点。

## 能力真实性边界

当前可以真实演示：

- 六面封闭矩形箱中的流体、整体 X 墙移动和连续注水；
- sphere、torus、box 三类均匀密度刚体；
- 水与刚体的双向作用、拖拽和射线推力；
- 表面张力、粒子/网格/SSFR 视图与 GPU timing。

当前不能真实声称：

- 局部闸门、开放出口、真实河道地形或建筑边界；
- 工程黏度、多液体、泥沙、渗流、冲刷、材料断裂；
- 工程量化水位、流量、承载、结构安全或洪水风险结论；
- XSPH 等同于现实黏度，或页面参数对应标准物理单位标定。

## 下一步扩展优先级

### P0：让差异可测、可重播

- [x] 五个使用场景的数据化 A/B 配置。
- [x] 单实例顺序 A/B、精确整数 solver-step 封顶、精确来水预算和自动冻结。
- [x] 六阶段时间线与目标/实际步数、输入、采样审计。
- [x] 粒子 P05/P95、两半区计数/P95、扩散、刚体位姿、实际边界与 A/B/Δ 结果卡。
- [x] 自动对照与自由探索状态分离。
- [x] 五个应用场景全部完成硬件 A/B 自动回归。
- [ ] 引擎级 60Hz tick / `step(n)` 桥接，以及中间事件与采样 tick 清单。
- [ ] GPU 小型归约探针：用 256–512B 回读替代当前约 1MB 冻结快照，并增加瞬时截面方向代理。
- [ ] 同 tick 关键帧、时间序列和 A 重跑一致性回归。
- [ ] 在同一场景内切换 particle / mesh / SSFR 证据视图。

### P1：让场景真正长成空间

1. 多个静态 box 边界。
2. 局部平移/旋转闸门与开放出流。
3. 高度场或 glTF → SDF/体素静态碰撞。
4. 参数化喷口、容器和障碍布局。

### P2：新增求解能力

- 复合刚体与非均匀质量，用于浮台、船体和偏载；
- 多液体、泡沫、喷雾和更明确的黏性模型；
- 泥沙、侵蚀、渗流和断裂属于新求解器方向，不能靠场景包装得到。
