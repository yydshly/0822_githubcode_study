## 一句话结论

它是一条“故事规划与图片生成 + 确定性视频合成”的 Agent 工作流：先把中文故事拆成静态手绘分镜，或导入用户已有图片，再用 FFmpeg 派生黑白层，最后由 Remotion 把文字、线稿和彩色稿按时间轴揭示并输出静音 MP4。

它不是端到端的视频生成模型。视频中的核心视觉素材仍是逐场景静态图，动态感主要来自遮罩揭示、分镜串联和可选卷页转场。这种取舍降低了生成成本，增强了版式、时长和编码的可控性，但运动丰富度、人物连续性和生产自动化仍有明显上限。

在线可操作版本见 [交互演示](https://yydshly.github.io/0822_githubcode_study/demos/story-to-handdrawn-video/)。首屏现在是知识可视化叙事工作台；下游研究区继续使用内联 SVG 重现上游三阶段机制，并把家庭记忆、知识解释、儿童成长、悬疑档案、品牌起源、诗性独白、古诗词场景与科技人文八套处方接入真实生图、MiniMax 中文 TTS、确定性文字层和十条 H.264/AAC 成片。古诗词处方包含《忆江南》诗卷讲解、明亮欣赏与《枫桥夜泊》夜色诗境，科技人文包含可恢复的停电体验、电力依赖图与真实成片。

研究页之外新增了独立的 [`Knowledge Video Studio`](../../docs/demos/story-to-handdrawn-video/studio.html)，把“理解这个库”与“使用这套能力生产视频”分成两个页面。生产台提供目标、方案、分镜、声音、成片、交付六步工作流，可选择知识样例、编辑学习目标、审核五幕、逐镜头锁定或重生成、配置 MiniMax 音色与语速、选择手绘处方和成片比例、查看任务日志，并导出不含密钥的 `knowledge-video-project/v1` 项目包。研究页在导航、首屏和知识规划器中均可进入生产台，生产台也可返回研究页查看原理、样片与证据。

生产台静态打开时明确使用演示模式：状态和流程真实可操作，但不会伪装成实时模型结果，也不会消耗 API 额度。页面预留 `http://127.0.0.1:8789/api/health` 安全服务检测入口；正式接入时由本地 Node 服务或云端后端持有 MiniMax Key、队列、下载与 FFmpeg 长任务，浏览器只提交经过人工审核的结构化项目。设计与支持边界见 [`PRODUCT_STUDIO_CONTRACT.md`](PRODUCT_STUDIO_CONTRACT.md)。

## 产品化落地：知识可视化叙事工作台

产品目标不是自动制造“看起来像知识”的视频，而是把专业知识转成观众愿意看、能够懂、记得住并可以迁移的视觉叙事。页面主流程为：

`知识意图 → 教学设计 → 五幕视觉叙事 → 可信边界 → 理解检测 → 生产交付`

用户可以填写知识主题、目标受众、目标时长、学习目标、常见误解、生活化入口和材料依据；也可以从“天空为什么是蓝色”“古诗如何构建空间”“停电为何让系统显形”三个完整样例开始。浏览器本地规划器随后输出：

- 面向指定受众的学习承诺；
- 问题、误解、机制、证据和迁移五幕，每幕含画面、旁白、证据位置与时长；
- 对现有八类叙事处方的完整评分，以及连接真实成片的第一推荐；
- 可核验事实、解释观点、艺术化表达和发布前审阅四层可信边界；
- 核心概念、误解修正和迁移应用三道理解题；
- 生图、TTS、字幕、审片与多规格导出的生产清单，以及可下载的 `knowledge-video-plan/v1` JSON。

当前 MVP 的规划、评分与导出完全在浏览器本地运行，不调用大模型，也不会把用户输入上传。任意新主题的真实图片与旁白仍需进入受保护的后端生成任务；医学、法律、安全等高风险主题必须经过专业审阅。这个边界避免把原有开源库、规则导演和模型能力混成一个不可审计的“一键 AI”。

优先使用场景包括学校微课、科学机构与知识创作者、博物馆和古诗词传播、公共服务与公益科普、职业培训，以及以技术原理和真实工艺为核心的品牌教育。后续扩展分为四层：教学层增加前置知识、分龄难度和前后测；可信层增加来源、版本与专家审批；生产层增加单幕重生成、多语言、成本和失败重试；评估层以理解率、误解减少和迁移能力替代单一播放量。

## 全能力交互演示

研究页不是单张效果图，而是一套本地可操作的能力控制台，按用户评估顺序分为三部分：

1. **全量能力**：切换故事文本与有序图片入口；编辑故事并动态生成 storyboard；操作 `plan/generate/full/import/render/preview` 六种模式、20 种画风、Codex/API 生成器、font/image2 字幕、cut/page-flip 转场、预览/正式输出；同时查看 CLI、Storyboard 和 Manifest。
2. **整合与扩展**：先通过叙事导演台把家庭记忆、悬疑档案、知识解释、儿童成长、品牌起源、诗性独白或古诗词场景映射为匹配的画风、色彩、镜头、转场、TTS、节奏和五段场景；再把故事、歌词/情绪 MV、漫画图片或文档统一映射到 Storyboard，组合手绘故事、情绪 MV、白板讲解、漫画翻页或古诗空间导览模板，以及 TTS、自动 QC、品牌规范和任务队列。
3. **使用场景**：对情绪故事、知识讲解、漫画翻页、品牌栏目、长篇连续剧、动作视频和高风险事实内容逐项给出适配度、推荐能力与仍需补齐的模块。

20 种画风在页面中完整展示其配方 id、中文名、适用方向与上游仓库自带的真实参考图；所有参考图使用统一题材，方便比较笔触、色彩和造型差异。中央合成舞台仍只做机制级模拟，不代表 20 次实时模型生成或质量横评。真实图片导入、FFmpeg 分层和 Remotion MP4 的验证结果仍以 `EVIDENCE.md` 为准。

## 真实整合案例

“02 · INTEGRATE & EXTEND”现在可直接播放《未发生的团聚》：一个关于“生成的记忆能否成为历史证据”的五节拍伦理故事。它不是装饰性样片，而是可核验的整合产物：

- 4 张分镜由本次内置图像生成能力真实生成，并用角色锁保持顾岚的银色发缕、圆框眼镜、服饰和统一水彩速写质感；
- 第 5 节拍有意复用第一幕并做确定性暖色回环，用来演示素材复用和循环叙事，而非假称为第 5 次生成；
- 5 段中文旁白由 MiniMax 中国区官方同步 T2A API 真实生成：`speech-2.8-hd` + `female-chengshu` + `calm`，32kHz WAV，按真实时长拼接；
- FFmpeg 完成镜头运动、0.4 秒交叉转场、ASS 中文字幕烧录和 H.264/AAC 合成；最终 MP4 为 720×960、30fps、54.333 秒；
- 页面时间轴可跳转到原则、谜题、供认、质问和选择五个叙事节拍，并同时展示生成、TTS、合成与媒体质检证据。

调用使用既有 Token Plan Key，请求发送至 `api.minimaxi.com/v1/t2a_v2`，本次共计 438 个计费字符。Key 只从仓库外的私有 `.env` 注入生成进程，未复制进仓库、页面或媒体清单。案例设计、媒体清单与边界说明见 [`REAL_DEMO.md`](REAL_DEMO.md)。

第二条真实案例《记忆不是录像带》用于验证“故事类型决定效果”而不只是更换风格名称。它把知识解释拆成误区、模型、机制边界、实验证据和行动迁移五幕；5 张 Codex imagegen 白板分镜保持暖白纸、炭黑线和单一概念蓝，MiniMax `speech-2.8-hd` 以 neutral 情绪合成 690 个计费字符，最终得到 77.333 秒的 720×960 H.264/AAC 成片。切换导演台的“知识解释”即可播放并按五个节拍跳转；制作规则、科学边界与适用场景见 [`KNOWLEDGE_DEMO.md`](KNOWLEDGE_DEMO.md)。

第三条真实案例《她先学会听风》验证儿童成长需要与前两类完全不同的叙事语言。5 张暖光水粉/彩铅分镜以第一幕为角色与纸鸢参考，保留小满的服装、同一水塔和终幕修补痕迹；MiniMax `speech-2.8-hd` 使用 `female-tianmei`、`calm`、0.96× 合成 923 个计费字符，最终成片为 107.267 秒。故事的成长证据是“蛮力失败 → 自主观察 → 奖带变尾翼 → 先松后收”，而不是由成人宣布道理。完整设计见 [`CHILDREN_DEMO.md`](CHILDREN_DEMO.md)。

第四条真实案例《封存之后，钟还在走》验证悬疑档案需要“线索可回看、翻转有证据、结尾保留责任”的效果语言。5 张严格炭黑/旧纸/铁锈红木刻分镜共享沈砚、青岬站、机械钟和物证锁；MiniMax `speech-2.8-hd` 使用 `male-qn-jingying`、`calm` 生成 5 段旁白，最终成片为 135.262 秒。旧报告、录音、口述证词、维护记录和违规进入被分层保存，避免把反转技巧或孝心叙事当成事实核验。完整设计见 [`MYSTERY_DEMO.md`](MYSTERY_DEMO.md)。

第五条真实案例《把瑕疵留在正面》用同一把开裂弯木椅验证品牌价值是否能由“问题 → 有代价的选择 → 可复查工艺 → 有边界的证据 → 开放邀请”成立。5 张有机轮廓水粉分镜锁定林又、椅子、珊瑚色蝴蝶榫和森林绿工作室语言；MiniMax `speech-2.8-hd` 使用 `Chinese (Mandarin)_Sincere_Adult`、`calm` 生成 1412 个计费字符，最终成片为 134.000 秒。完整设计见 [`BRAND_DEMO.md`](BRAND_DEMO.md)。

第六条真实案例《潮水把名字还给岸》验证诗性效果也能被结构约束。渡口、现代桥、录音机与褪色朱红线在五幕中反复变义，故事明确承认新桥的公共便利，不让私人怀旧要求别人退回旧生活。5 张当代水墨分镜配合确定性低幅环境声；MiniMax `speech-2.8-hd` 使用 `Chinese (Mandarin)_Lyrical_Voice`、`calm` 生成 1007 个计费字符，最终成片为 127.633 秒、1280×720。完整设计见 [`POETIC_DEMO.md`](POETIC_DEMO.md)。

第七条案例选择张继《枫桥夜泊》，不是把诗句逐字配图，而是把“月落乌啼—江枫渔火—对愁眠—姑苏城外寒山寺—夜半钟声到客船”还原为天时、近岸、人物、远景和声音抵达五层关系。5 张 16:9 夜色水墨分镜由第一幕视觉锚点约束同一客船、旅人、桥与寺塔方向；朗诵和解读使用 MiniMax 官方 HTTP T2A，终幕钟声由确定性合成负责。页面同时呈现原文、可观察意象、空间关系和“艺术化还原并非历史证据”的边界。完整脚本与视觉锁见 [`CLASSICAL_POETRY_DEMO.md`](CLASSICAL_POETRY_DEMO.md)。

同一古诗词处方的鲜明对照选择白居易《忆江南·江南好》。五幕用“赞叹 → 熟悉 → 日出 → 红绿对照 → 回望”组织诗意，5 张连续 16:9 分镜锁定同一水乡、拱桥、小舟与回望者，并以日出朱红、江花珊瑚红、孔雀绿春水和湖蓝空气建立高明度视觉证据。MiniMax `speech-2.8-hd` 使用 `Chinese (Mandarin)_Lyrical_Voice`、`happy` 合成 805 个计费字符；确定性合成加入低幅春水和克制鸟鸣，得到 116.420 秒、1280×720 的 H.264/AAC 成片。网页将其保留为“明亮欣赏”切换项，并允许继续比较夜色版。设计与边界见 [`BRIGHT_CLASSICAL_POETRY_DEMO.md`](BRIGHT_CLASSICAL_POETRY_DEMO.md)。

诗词讲解不能只在欣赏视频底部叠长字幕，因此 Revision 14 复用同一批分镜和 MiniMax 音轨，另行生成《忆江南》诗卷讲解版。16:9 画布左侧只承担意象证据，右侧常驻标题、作者和完整原诗；五幕分别高亮“江南好、旧曾谙、日出、红/绿比较、能不忆”，同步显示关键词、释义与画面证据。讲解信息由确定性 ASS 排版进入诗卷，不再以底部字幕承担主要内容。网页默认打开讲解版，并可切换明亮欣赏和夜色诗境。

## 故事—效果叙事导演扩展

Revision 6 在真实案例和统一生产架构之间新增了一个数据驱动的叙事导演台。它回答的不只是“选哪种画风”，而是把内容类型同时映射为视觉语言、时间语言和声音语言：

| 故事类型 | 核心叙事弧 | 默认风格 | 推荐模板 |
| --- | --- | --- | --- |
| 家庭记忆 | 原则 → 异常 → 缺口 → 质问 → 回响 | 彩铅日记漫画 | 手绘故事 |
| 悬疑档案 | 异常 → 追踪 → 误导 → 翻转 → 余波 | 粗粝木刻社论插画 | 手绘故事 |
| 知识解释 | 误区 → 模型 → 机制边界 → 实验证据 → 迁移 | 白板讲解动画 | 白板讲解 |
| 儿童成长 | 愿望 → 蛮力受挫 → 观察 → 主动改造 → 带痕成长 | 暖光童画绘本 | 翻页绘本 |
| 品牌起源 | 问题 → 选择 → 工艺 → 证据 → 邀请 | 有机轮廓品牌涂鸦 | 手绘故事 |
| 诗性独白 | 意象 → 回声 → 反差 → 空白 → 余味 | 水墨写意 | 情绪 MV |
| 古诗词场景 | 由原诗决定：明亮回望或夜色羁旅 | 鲜明设色 / 夜色水墨双版本 | 古诗空间导览 |

每套处方包含色彩弧线、镜头原则、转场语法、MiniMax 音色/情绪建议、整体节奏，以及五幕各自的环境、主体、意义、画面指导、效果动作和旁白意图。选择故事后，推荐模板会同步到原有组合器；“在 20 种风格中定位”则把处方连接回上游真实风格参考。

当前导演台刻意采用本地规则表，因此可离线运行、结果可重复，也不会把预设冒充成大模型实时推理。产品化接入模型时，模型负责从用户内容中提取人物、物件、冲突、主题与事实约束，再选择或修订这套可审阅处方；Storyboard 仍是模型判断与确定性渲染之间的边界。

## 故事输入与效果对齐实验台

Revision 12 把七条研究样片整理成可直接试用的产品入口。用户可粘贴自己的故事，或选择家庭记忆、知识解释、儿童成长、悬疑档案、品牌起源、诗性独白、古诗词场景七个内置样例；页面会在本地提取人物关系、解释结构、儿童行动、证据链、工艺承诺、重复意象、诗体标记和空间意象等叙事信号，并输出七类完整分数、第一推荐理由、风险提醒和五幕结构建议。

推荐不是停在文字上：“打开第一推荐的真实样片”会同步叙事导演台、回到第一幕、显示对应 Codex 生图 + MiniMax TTS 成片，并暂停隐藏其他媒体。下方七路比较卡把每类的叙事弧、视觉语法、声音与节奏、最佳场景和主要风险放在同一视图中，也可分别直达真实样片。

这一层是无网络、可复现、可审阅的关键词与结构加权原型，不是 LLM 语义理解，也不会调用 MiniMax 或图像 API。它证明的是产品决策链和交互闭环。正式产品可让大模型把自由文本抽取为人物、物件、冲突、事实、品牌和审美约束，再由这套结构化规则给出可解释候选；用户确认后才进入生图、TTS、单幕重生成与确定性合成。

### MiniMax 安全配置与复用

## 它实现了什么

项目由两个可以独立理解、组合使用的部分构成：

1. **Agent Skill**：定义自然语言入口、默认风格约束、素材生成步骤、输出契约和风险规则。Agent 负责理解用户意图并调度脚本。
2. **Remotion 渲染器**：把 storyboard、图片层和转场变成 3:4 竖屏 H.264 静音视频。

支持两条输入路径：

| 输入 | 中间产物 | 核心处理 | 输出 |
| --- | --- | --- | --- |
| 中文故事文本 | 分镜 JSON、提示词、Image2 job manifest、场景主图 | 规则分句、风格锁、人物锁、图片生成、黑白层派生 | 正式 1080×1440 或预览 720×960 静音 MP4 |
| 有序本地图片 | 上传素材 manifest、分镜 JSON、裁切后的文字/插画层 | 去重、版式检测、文字/插画分区、灰度线稿派生 | 同上，可选直接切换或卷页转场 |

已实现的显著能力包括：

- 中文故事按完整句子和叙事转折拆成节拍；
- 20 种内置手绘风格，可按编号、id、中文名和别名选择；
- 默认“彩铅日记漫画”有固定参考板和严格视觉锁；
- 人物参考图、场景连续性参考、分镜级视觉计划；
- 默认字体渲染字幕，避免生成模型写错中文字；
- `文字 → 黑白画稿 → 彩色插画` 从左到右逐层揭示；
- 上传整页图片时自动判断是否存在上方文字区；
- 可选右下角卷页效果；
- 内容寻址的素材批次，输入或风格变化时自动换缓存目录；
- 预览和正式渲染分离，最终产物明确保持静音，便于后期配音。

## 工作原理

完整链路如下：

```text
自然语言请求
    │
    ▼
Agent Skill：确认输入、风格、模式和约束
    │
    ├─ 故事文本 ──► 规则分句/换行/估算时长
    │                  │
    │                  ▼
    │              风格锁 + 人物锁 + visual plan
    │                  │
    │                  ▼
    │              Codex Image2 job manifest
    │              或 OpenAI API 图片生成
    │
    └─ 有序图片 ──► SHA-256 去重 + 版式检测/裁切
                       │
                       ▼
               FFmpeg 生成 caption / bw / color 层
                       │
                       ▼
                 storyboard JSON
                       │
                       ▼
       Remotion：Sequence + clip-path + SVG 卷页
                       │
                       ▼
       H.264、30fps、3:4、静音 MP4
```

### 1. 文本变成分镜节拍

[`scripts/story-to-video.mjs`](https://github.com/gnipbao/story-to-handdrawn-video/blob/fbab5b27f4f0db61739d86f78000a39eeaa692d3/scripts/story-to-video.mjs) 使用中文标点、最大长度 36 字和“后来、突然、但是、于是”等叙事转折词进行规则切分。每个节拍再按每行最多 13 字、最多 3 行排字幕，并依据行数和字数把场景时长限制在约 4.4–6.2 秒。

这不是 LLM 分镜器，而是可预测的启发式算法。复杂指代、时间跳跃、医疗或年龄敏感场景由外部 `visual-plan` JSON 补充，而不是由脚本自动推理。

### 2. 风格和人物连续性被写入提示词

风格库是 [`references/handdrawn-style-library.json`](https://github.com/gnipbao/story-to-handdrawn-video/blob/fbab5b27f4f0db61739d86f78000a39eeaa692d3/references/handdrawn-style-library.json)。程序把风格配方、负面约束、参考图内容一起计算 SHA-256 指纹，再把指纹放入素材批次 hash。这样更换风格或参考图后，不会误用旧素材。

Codex 路径先生成一张主角 reference sheet，再让每个场景同时参考风格图和人物图。API 路径则把上一场彩色图作为下一场的连续性参考。两种方式都依靠提示词和参考图维持人物一致性，没有独立的角色模型或身份相似度校验。

### 3. 一张主图派生多层素材

每个故事场景只生成一张主图：

- `font` 模式生成 1024×1024 无字插画，字幕由 Remotion 字体绘制；
- `image2` 模式生成 1024×1536 的“上方文字 + 下方插画”母版；
- FFmpeg 从母版裁出文字层和彩色插画层，并通过灰度、对比度和锐化滤镜派生 `bw` 层。

因此黑白线稿并不是另一张独立生成图，而是彩色稿的本地灰度衍生物。好处是图层天然对齐，成本低；代价是它不是真正的作画过程或骨架线稿。

### 4. storyboard 是生成端和渲染端的边界

脚本最终生成 `Storyboard`：项目级配置包含画布、帧率、转场、风格锁和音频契约；场景级配置包含时长、字幕、叙述、层序和素材路径。这个 JSON 是全系统最适合扩展和测试的稳定边界。

### 5. Remotion 负责确定性动画

[`src/Scene.tsx`](https://github.com/gnipbao/story-to-handdrawn-video/blob/fbab5b27f4f0db61739d86f78000a39eeaa692d3/src/Scene.tsx) 根据每场总帧数安排三个阶段：字幕先出现，黑白稿随后揭示，彩色稿最后覆盖。`LayerWipe` 和 `TextWipe` 都通过 CSS `clip-path: inset(...)` 实现从左到右的擦出。

普通模式用 `Series` 顺序播放场景；卷页模式用重叠 `Sequence`、SVG 贝塞尔路径、clipPath、渐变和阴影模拟纸张从右向左卷起。最终由 Remotion/Chrome 逐帧绘制并编码 H.264。

## 适用场景

### 很适合

- 情感故事、家庭日记、成长回忆等“旁白 + 静态插画”短视频；
- 知识讲解、流程说明、观点拆解、时间线类白板动画；
- 把已有漫画页、儿童画、旅行手账或品牌插画快速变成动态画面轨；
- 同一栏目批量生产统一比例、统一风格、统一节奏的视频；
- 需要把画面与配音制作解耦的后期工作流；
- 用低成本预览先确认分镜，再决定是否生成高清素材。

### 不太适合

- 需要连续人物表演、口型、复杂运镜、打斗或物理运动的内容；
- 需要精确控制每个动作时刻或逐字对齐配音的成片；
- 长篇、多角色、多地点且要求严格人物一致性的连续剧；
- 无人工审片的医疗、法律、新闻、儿童安全等高风险内容；
- 横屏、多平台自适应或丰富音频交付——当前画布、布局和音频契约较固定；
- 希望“一条命令全自动完成 Codex 内置图片生成”的无人值守流水线；Codex manifest 仍需要 Agent 执行图片 job 并导入。

## 架构优点

- **把概率生成和确定性渲染分离**：图片可能不稳定，但时间轴、版式和编码可重复。
- **一次生成，多层复用**：本地派生黑白层，减少图片生成次数并保持像素对齐。
- **中间契约清楚**：storyboard 和 job manifest 让计划、生成、导入、渲染可以分阶段审阅。
- **默认文字准确**：字体字幕规避 AI 生成中文常见的错字和乱码。
- **素材缓存可解释**：故事、风格、角色锁和视觉计划共同决定批次 hash。
- **上传路径务实**：不用重绘用户图片，也能得到统一版式、揭示动画和卷页效果。

## 当前限制与风险

1. **项目不是完整的干净克隆即用状态**：上游未提交示例 storyboard 所引用的 `public/assets/generated/**`，所以 `npm run check` 的 TypeScript 阶段通过，但随后素材存在性校验失败。
2. **Python 包装器在 Windows 上不可直接运行**：它通过 `subprocess.run(["npm", ...])` 调用 `npm`；本次 Windows 环境只有 `npm.cmd` 可解析，导致 `WinError 2`。直接调用 Node/npm 脚本可以绕过。
3. **图片生成并未完全自动化**：默认 Codex 路径先写 `codex-image-jobs.json`，仍依赖 Agent 逐个生成主图；API 路径依赖 `OPENAI_API_KEY` 和 Codex 内部 imagegen 脚本位置。
4. **人物一致性是软约束**：没有脸部/服装一致性评分、自动重试或跨场景 QC。
5. **非默认风格缺少固定参考板**：其余 19 种主要依赖提示词锁和单张示例，漂移风险更高。
6. **上传版式识别是阈值启发式**：通过缩略灰度图的逐行“墨迹比例”寻找空白沟槽，复杂排版可能误切，虽支持 `--split-y` 手工覆盖。
7. **画布和布局高度硬编码**：类型限定 3:4，字幕区和插画区使用固定像素坐标，扩展到 9:16 或横屏需要成组修改。
8. **动画表达有限**：擦除效果揭示的是完成图层，不是真实笔画路径；没有镜头、景深、角色部件或语义级运动。
9. **缺少完整测试体系**：目前主要是 TypeScript 静态检查和 storyboard 校验，没有单元测试、快照测试、视觉回归或 CI 工作流。
10. **依赖安全需要跟进**：本次 `npm ci` 报告 3 个 high severity 漏洞；尚未做依赖链归因和升级兼容性验证，因此只记录事实，不在本研究分支直接修改上游依赖。

## 最值得优先做的产品路线

如果目标是尽快形成可用产品，建议顺序是：

1. **先做“可审片的创作者工作台”**：编辑分镜、重生成单场、配音对齐、导出，价值最直接。
2. **再做“可靠的批量渲染服务”**：schema、队列、缓存、成本记录、QC、失败重试。
3. **最后做“更丰富的动画引擎”**：分层、矢量笔画和角色运动，因为这会显著提高素材与工程复杂度。

不建议一开始把重点放在继续增加风格数量。项目已有 20 种风格，但目前影响规模化生产的主要瓶颈是人物连续性、审片修订、配音同步、跨平台布局和任务可靠性。

## 停电体验与电力依赖显影

科技人文样片前增加了一段约 8 秒、完全由用户触发的交互序章。页面依次进入 `powered → outage → phone → reveal → ready → restore`：供电状态下风扇、路由器与城市灯光工作；断电后运动和灯光同时停止；手机微光随后出现；最后用动画路径把房间连接到发电、升压与输电、城市变电、社区配电、插座与设备。断电和复电提示由浏览器 Web Audio 即时合成，不加载额外音频，也不调用 TTS 或外部 API。

系统图提供四个观察入口：风扇/空调、家庭路由器、手机网络、泵与电梯。每个入口都区分“设备仍有电池”与“上游网络或建筑基础设施是否供电”，避免把所有停电影响说成即时、绝对或全球一致。用户可以直接跳过序章、恢复供电、按 `Escape` 复位，或带着当前理解进入正片；`prefers-reduced-motion` 会保留全部阶段信息，但取消连续旋转和渐移动画。JavaScript 不可用时，十条成片直链仍然存在。

## 独立生产台：从网页完成真实生成链路

研究页继续用于解释能力、样片与场景；独立生产台位于 `docs/demos/story-to-handdrawn-video/studio.html`，用于实际推进“目标 → 五幕方案 → 分镜 → MiniMax 配音 → FFmpeg 成片 → 交付”。真实模式由 `integrations/studio-server.mjs` 提供，只绑定本机回环地址，API Key 只从被 Git 忽略的 `.env` 读取，不进入网页、项目清单或导出包。

生产台的四个预设不是只替换表单文案：天空、用电、《忆江南》和 AI 耗电分别绑定独立的五幕方案、五张分镜、MiniMax 正式音轨、最终 MP4 与来源清单。`activePreset` 会随项目持久化；切换预设会清除上一任务的计划、锁定、声音和成片状态，直接 `file://` 也不会回退到天空素材。实时服务返回的项目资产始终优先于预设参考资产。

```powershell
Copy-Item .env.example .env
# 在 .env 中填写 MINIMAX_API_KEY；不要提交 .env
node integrations/studio-server.mjs
```

随后打开 `http://127.0.0.1:8789/demos/story-to-handdrawn-video/studio.html`。如果端口被占用，可以先设置 `STUDIO_PORT`。不启动服务或直接用 `file://` 打开时，页面明确保持演示模式，不会把样例动画说成真实 API 结果。

离线验收可以设置 `STUDIO_MOCK=1`：它不会调用 MiniMax，会复用固定参考素材，但仍执行真实 WAV 拼接、字幕生成和 H.264/AAC 合成。真实服务已以 MiniMax-M3、image-01、speech-2.8-hd 完成一条 5 幕、81.133 秒的知识视频闭环。当前视觉生成仍是概率结果；角色连续性、伪文字和科学图示必须人工审核，页面不会把这两项冒充为自动通过。

### 故事优先的高质量混合链路

“为什么 AI 那么耗电”样例进一步把生产链从“多个 API 顺序调用”改为质量分层。事实与学习目标先限定可讲范围；故事导演层形成唯一五幕契约，每幕同时给出旁白、画面任务、禁止内容和可信边界。图片与声音都消费这份契约，而不是各自重新理解主题。

- **故事讲解是核心**：模型草稿之后增加事实人工复核，删除了“上百台设备同时被唤醒”等无法由材料支持的表述。
- **图片是关键质量层**：MiniMax Image 只用于探索构图；因伪文字、水印感和跨幕风格漂移，五张最终图全部由 Codex 统一重绘。项目清单保留初稿提供方和逐幕返工原因。
- **TTS 是稳定执行层**：画面和旁白锁定后再调用 MiniMax `speech-2.8-hd`，它只负责语音与真实时长，不改写内容。
- **合成是确定性层**：字幕、音轨、手绘表达和 H.264/AAC 编码由本地渲染器与 FFmpeg 完成。

最终成片为 1280×720、79.2 秒。研究页直接展示视频、五幕跳点和来源清单；生产台的“AI 耗电 · 一键到成片”会复现这次已经完成并人工复核的真实混合任务，因此从 `file://` 也可完整演示，且不会重复消耗 API 额度。新主题仍可通过本地安全服务逐步生成和审核。
