# 扩展路线图

## 目标原则

- 先提高可复现性和可修订性，再增加视觉花样；
- 把图片生成成本、失败和人工审片视为正常流程；
- 保留“概率生成素材、确定性渲染视频”的核心架构；
- 任何新能力都通过版本化数据契约连接，不继续堆积单体脚本。

## Phase 0：可靠开发基线（1–2 周）

- 修复 Windows `npm.cmd` 解析；
- 拆分结构校验与素材存在性校验；
- 提交可再分发的最小测试 fixture；
- 为分句、字幕换行、风格解析、hash 和总帧数添加测试；
- 加 GitHub Actions：Node 20/22 × Windows/Linux；
- 归因并处理 npm 高危依赖；
- 增加 storyboard 与 manifest schema version。

验收：干净克隆在所有支持平台上能安装、运行 plan-only、校验 fixture 并渲染 2 秒预览。

## Phase 1：创作者最小产品（3–6 周）

- Web 项目创建与故事粘贴；
- 场景列表、分句编辑、时长和视觉方向修改；
- 风格对比、人物设定和参考图上传；
- 单场生成、单场重试、人工批准；
- 上传图片裁切预览与手工 split line；
- 低清预览和高清导出；
- TTS、SRT 与基础配音对齐；
- 每次生成的 prompt、模型、成本和 hash 可追溯。

验收：用户不碰命令行即可完成“故事 → 审片 → 修订一场 → 配音预览 → 导出”。

## Phase 2：规模化内容流水线（4–8 周）

- 异步任务队列、断点续跑、重试和并发限额；
- Generator adapter 与多供应商策略；
- 对象存储、素材去重、生命周期和 CDN；
- 人物一致性、文本、裁边、风格和安全视觉 QC；
- 多比例 layout template；
- 批量栏目、品牌 kit、团队审批；
- 渲染耗时、失败率、生成成本和返工率观测。

验收：100 个场景级任务能在预算和并发约束下稳定完成，失败可定位、可重跑，素材和审核状态不丢失。

## Phase 3：动画表现力（持续）

- SVG/路径级逐笔绘制；
- 前中后景分层与轻量视差；
- 受限镜头推拉和平移；
- 风格感知的转场 registry；
- 角色部件与表情系统；
- 导出到剪辑软件时间线。

验收：新增动作不破坏当前“安全不裁切、文字准确、低成本、可后期”的产品约束。

## 建议跟踪指标

- 首次可用预览时间；
- 单分钟成片生成与渲染成本；
- 场景一次通过率和平均重试次数；
- 人物一致性/文字准确性 QC 通过率；
- 用户手工调整场景比例；
- 预览到正式导出的转化率；
- 渲染失败率和 P95 时长。
