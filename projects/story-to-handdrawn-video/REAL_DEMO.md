# 真实整合案例：《未发生的团聚》

## 演示目标

验证“叙事规划 → 连续生图 → 中文 TTS → 字幕时间轴 → 确定性视频合成 → 页面播放”这条整合链路，而不是只展示架构方块。

## 故事命题

一张由残片和生成模型拼合的团聚照，是否可以进入历史档案？案例不把问题简化成“AI 是好是坏”，而是区分三种东西：

- 原始残片是可核验的事实证据；
- 生成过程必须保留来源和修改记录；
- 合成照片不是真实历史，却可能承载真实的思念。

顾岚最终不把合成图冒充历史，也不删除它，而是把残片、生成过程和口述记忆共同保存。

## 五个叙事节拍

1. **原则**：顾岚在雨夜档案馆修复旧照片，相信档案只负责事实。
2. **谜题**：她发现一张拍摄日期晚于月台拆除时间的团聚照。
3. **供认**：何伯说明女儿失联，照片来自两张残片和生成模型。
4. **质问**：外孙女提出“没有发生的团聚能否包含真实思念”。
5. **选择**：画面回到档案馆，以同一场景的暖色收束；顾岚把事实、过程和记忆分层保存。

## 媒体边界

- 分镜 1–4 使用内置图像生成能力真实生成；第 5 节拍有意复用第一幕并做确定性色彩变化，展示素材复用与循环叙事。
- 中文旁白由 MiniMax 中国区官方 HTTP T2A 接口真实生成：`speech-2.8-hd`、`female-chengshu`、`calm`、32kHz WAV，不依赖浏览器 `speechSynthesis`。
- 字幕与场景按可检查的时间表烧录进 MP4。
- Token Plan Key 仅在本地生成进程运行时从仓库外私有 `.env` 读取，没有写入仓库、页面或媒体文件；本次 5 段语音共计 438 个计费字符。
- 后续复用通过可提交的 `.env.example` 与 `integrations/minimax-tts.mjs` 完成；真实 `.env` 和中间音频目录已加入忽略规则，Key 不接受命令行参数，也不会出现在日志中。
