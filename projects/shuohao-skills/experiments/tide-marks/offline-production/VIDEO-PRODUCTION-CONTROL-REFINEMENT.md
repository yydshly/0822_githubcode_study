# 视频生产控制台修复与验收记录

## 设计契约

- 入口模式：Repair-led（根据现有页面截图修复）。
- 请求版本：1。
- 目标用户与场景：没有编程经验的中文用户，在外部平台生成《潮痕》视频后，回到本地页面登记、质检并继续下一段。
- 第一印象：明确区分“素材已准备”和“视频生产进度”，一眼知道下一步做什么。
- 视觉目标：Functional。
- 体验架构：Editorial Flow。
- 保留：深色视觉系统、59 段计划、193 镜剪辑表、逐段上传顺序与提示词入口、纯静态离线运行。
- 信息约束：不能把 59/59 可投产误写成 59/59 已生成；必须说明页面不会监控下载目录。
- 操作约束：无需后端；支持逐段登记、批量选择生成视频、按段号匹配、状态/QC筛选、JSON 备份与恢复。
- 状态约束：进度保存在当前浏览器 localStorage；文件只记录名称和元数据，不保留浏览器临时访问地址；重建 HTML 不得破坏原始 CSV 台账。
- 环境约束：必须能从 `file://` 打开；不依赖网络服务。
- 主流程：选择/拖入含段号的视频 → 自动匹配段 → 标为待质检 → 用户登记 QC → 进度 KPI 与下一段同步变化 → 导出进度备份。
- 用户授权：用户指出问题并询问如何驱动变化；允许执行可逆的本地页面修复。
- 用户决策边界：不连接真实 H3 API，不监控下载目录，不自动移动或覆盖视频文件。
- 完成标准：表头不覆盖首行；页面说明清晰；E01-01 测试视频可被匹配并更新；刷新后状态保留；JSON 可导出/导入；桌面及窄屏主要操作可达。

## 初始修复台账

- 当前阶段：Stage 1～3。
- 浏览器环境：Windows Chrome，`file:///E:/0822_codex_project/projects/shuohao-skills/experiments/tide-marks/offline-production/video-production-control.html`，截图约 1657×856，深色主题。
- 已观察问题：筛选栏和表头都使用 sticky；表头固定 `top:64px`，但筛选栏实际换行/高度可能变化，导致表头覆盖第一条数据；页面只有筛选功能，状态文字由构建时静态写入。
- 根因：表头定位使用硬编码高度；没有运行期状态模型和用户可操作入口。
- 最小完整修复：取消表头相对视口的第二层 sticky，改为表格容器内普通表头；增加离线状态控制层，不接入后端。
- 邻接检查：筛选栏滚动、横向表格、桌面首行、390px 操作、刷新持久化、原链接可访问。
