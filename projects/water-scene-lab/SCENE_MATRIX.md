# 水场景技术选择矩阵

## 先定义宏观目标，再拆解技术

每个水场景先回答五个问题：

1. **空间尺度**：杯、池、河段、瀑布、海面还是区域地形？
2. **主要运动**：自由飞溅、沿河道流动、周期波、落差破碎还是水位传播？
3. **关键交互**：是否需要物体排水、浮力、尾流、障碍阻挡或地形漫淹？
4. **真实性等级**：视觉叙事、游戏交互、教学概念还是工程计算？
5. **设备预算**：桌面独立显卡、普通笔记本还是移动浏览器？

只要这五项不同，最佳技术路线就可能不同。

宏观场景通常同时命中多条路线，因此本矩阵有两层用途：先把宏观场景拆成能力组合，再为每个能力缺口选择最小实验。

## 宏观场景—能力组合矩阵

| 宏观场景 | 水系链路 | 必需能力 | 第一批连接问题 | 当前状态 |
| --- | --- | --- | --- | --- |
| Mountain Watershed｜山地水系 | Source → River → Waterfall → Pool → Floodplain/Sink | River、Waterfall、Flood、按需 Local Liquid | 流量与单位、陡坎转换、落水沉积、水潭溢流 | `T3 slice passed / Flood active` |
| Coastal World｜海岸世界 | Ocean → Coast → Estuary → River/Harbor | Ocean、River、岸线、浮体、局部飞沫 | 河海交汇、波浪与水流共存、近岸衰减、船体查询 | `Ocean near-field reuse passed / full coast held` |
| Interactive Water｜局部互动水环境 | Source → Container/Pool → Overflow → Drain | Local Liquid、Pool、刚体、事件 | 注水/排水、容积、浮力、机关和视觉状态 | `capability-backed plan` |

能力模块不是宏观场景的替代品。例如 Mountain Watershed 不是“River 页面 + Waterfall 页面”，而是必须让 River 的输出成为 Waterfall 的输入，并继续影响 Pool 和 Floodplain。

## 场景—能力路由表

| 场景问题 | 首选最小路线 | 重点能力 | 可组合能力 | 不代表什么 |
| --- | --- | --- | --- | --- |
| 容器、池体、局部倾倒和刚体入水 | PBF 粒子 + Shape Matching + 屏幕空间/网格表面 | 自由液面、粒子碰撞、排水、浮沉、刚体耦合 | 泡沫、喷雾、任意碰撞体、音效 | 不是大尺度河海，也不是工程 CFD |
| 开阔海面、风浪和船体起伏 | Gerstner/叠加波 MVP；需要海况统计时再评估频谱 FFT | 大范围连续波面、动态法线、层级细节、表面高度/法线查询 | 船尾局部粒子、泡沫、天空与反射 | 视觉波面不自动等于真实船舶水动力 |
| 沿地形弯曲的河流和漂流 | 样条河道网格 + 流向图/UV 流动 MVP | 河道形状、方向、岸线、速度线索、漂浮标记 | 局部浅水、障碍激波、瀑布连接、河岸植被 | 流动纹理不是流量、流速或水位计算 |
| 有明显落差、破碎和雾化的瀑布 | 已验证基线：主水幕网格 + 有限破碎粒子；白沫/雾独立按需 | 连续落水轮廓、边缘分离、撞击区和飞沫；固定 A/B 只改 `breakupMode` | 上游河流、下游水池、白沫/雾、按宿主需求评估局部 PBF | 粒子数量与落点占用不等于流量或质量守恒 |
| 地形上的漫淹、围挡与水位传播 | 2D 高度场/浅水方程代理 | 水位传播、地形阻挡、溢流方向、时间对比 | 雨源、闸门事件、叙事标注、风险热区 | 未经校准不能用于防洪设计或真实预测 |
| 仅需远景水面背景 | 平面/低模网格 + 法线/反射/折射 | 低成本视觉语义 | 岸线泡沫、环境反射 | 不具备真实体积、浮力或物体耦合 |

## 子目标能力选择树

```text
是否必须表现自由飞溅、排水或物体进入液体？
├─ 是 → 局部粒子液体；只在交互区使用
└─ 否
   ├─ 是否是无限/开阔波面？ → Ocean 波面路线
   ├─ 是否沿明确河道定向流动？ → River 样条 + 流向路线
   ├─ 是否以高落差与雾化为主？ → Waterfall 混合 VFX 路线
   └─ 是否需要地形上的水位传播？ → Flood Proxy 高度场路线
```

如果一个场景同时命中多项，就组合局部模块，而不是把所有区域交给最昂贵的求解器。例如：海面由波面模型覆盖，船首两米范围叠加局部飞沫；河流主体用样条和流向图，在需要水位传播的河段运行浅水，在陡坎处转换为瀑布粒子或解析水束。

## 共用接口，而不是共用算法

| 共用接口 | 用途 | 最小约定 |
| --- | --- | --- |
| `time` | 保证波面、纹理、粒子和相机按同一时钟推进 | 支持固定步长、暂停和可重复播放 |
| `sampleSurface(x,z,t)` | 给浮体、镜头或标记查询水面高度和法线 | 返回高度、法线、有效标志；不伪造不存在的数据 |
| `sampleFlow(x,z,t)` | 给河面线索、方向箭头或漂浮标记查询方向与速度代理 | 返回方向、速度模长、有效域与真实性等级；视觉值不自动解释为实测流速 |
| `disturb(event)` | 将物体、风、闸门或落水事件传给对应模块 | 明确位置、半径、强度、持续时间和模块支持情况 |
| `receiveTransfer(transfer)` | 接收上游节点传来的水量、速度和方向 | 明确来源、单位、时间步、真实性等级和代表量 |
| `emitTransfers()` | 输出到下游节点 | 记录输入、输出、存量和残差；视觉质量不能改变代表水量 |
| `qualityTier` | 为桌面和移动端选择网格、粒子、反射与后处理预算 | 至少 `high / balanced / fallback` 三档 |
| `evidenceState` | 区分自由探索和固定实验 | 保存场景、参数、相机、输入、运行步数与设备信息 |
| `truthLevel` | 明确能力处于视觉、运动学、映射、耦合或校准哪一级 | 使用 `T0 / T1 / T2 / T3 / T4`，不能用视觉质量冒充物理等级 |

这些接口允许不同水体在同一场景中协作，但不会掩盖它们物理模型和真实性等级的差异。

## 常见误用

- 用数十万 PBF 粒子填满海洋：计算成本随局部细节扩大，远景却没有得到相应价值。
- 用滚动法线贴图代表容器液体：看起来在动，但不能产生排水、浮沉或边界碰撞。
- 把河流 flow map 的像素速度解释为真实流速：它只是着色坐标或视觉方向场，除非另有校准模型。
- 把瀑布飞沫数量解释为流量：粒子常是视觉采样，不保证连续质量。
- 用叙事洪水代理得出真实淹没范围：没有地形精度、边界条件、糙率、流量与历史数据校准时，只能表达概念关系。
