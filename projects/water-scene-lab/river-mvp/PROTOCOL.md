# River MVP 固定实验协议

## Particles4All Reuse Protocol

目标平台：桌面浏览器。第二场景复用必须读取 [`../scenes/river-obstacle-near-field.scene.json`](../scenes/river-obstacle-near-field.scene.json)，并使用与 Waterfall 相同的通用 Scene Runner；River 页面不得复制注入、步进或测量算法。

- world driver：`river-spline-flow-vector`；
- 固定采样：河道弧长 50%，切线 `(-0.617162, 0.786836)`；
- local frame：River tangent → solver `+X`；
- packet：`10 × 6 × 8 = 480`；
- solver velocity：`[2.5, 0, 0] u/s`；
- solver：36 ticks；
- Gate：实际注入、ticks、有限值、WebGPU context，以及刚体沿 `+X` 位移至少 `0.003 u`。

总位移不能代替方向位移；只有向下的重力响应必须失败。宏观样条河面仍不是 PBF，近场粒子也不等于现实流量或水深。

## 实验问题

在同一条固定弯曲河道中，世界固定方向场 A 与样条切线方向场 B，是否会让水面方向线索和漂浮标记产生可重复、可解释的空间一致性差异？

本协议只比较内部视觉方向规则，不回答真实流速、流量、水位、冲刷、通航或防洪问题。

## 固定契约

| 项目 | 固定值 |
| --- | --- |
| 模型 | `river-flowmap-v1` |
| 种子 | `602` |
| 步长 | `1 / 60 s` |
| 总步数 | `1,200`（20 秒） |
| 预热 | 前 120 步 |
| 统计区间 | 第 121–1,080 步，共 960 步 |
| 河道中心线 | 8 个固定 Catmull–Rom 控制点 |
| 河宽 | `6.8` 内部单位 |
| 速度模长 | `2.55` 内部单位 / 秒 |
| 漂浮标记 | 8 个固定起点与横向车道 |
| A | `flowMode = uniform_world`，方向始终为世界 `+Z` |
| B | `flowMode = spline_tangent`，方向为最近中心线切线 |
| 弧长采样 | `1,024` 个查找表区间 |
| 最近点粗采样 | `320` 个区间，再做 12 次局部三分细化 |
| 契约哈希 | `fnv1a-4b3a09ae` |

唯一主要实验因子为 `flowMode`。A/B 的河道、宽度、速度模长、标记起点、种子、相机、时间轴、渲染层和统计窗口相同。

## 固定中心线

| # | X | Z |
| --- | ---: | ---: |
| 1 | 0.0 | -30.0 |
| 2 | -1.4 | -22.0 |
| 3 | 5.8 | -14.5 |
| 4 | 7.2 | -5.5 |
| 5 | 1.4 | 3.5 |
| 6 | -6.8 | 11.5 |
| 7 | -5.2 | 20.5 |
| 8 | 0.0 | 30.0 |

中心线按分段 Catmull–Rom 插值，并解析计算一阶导数。归一化导数为切线 `T=(Tx,Tz)`，平面法线为 `N=(-Tz,Tx)`；河面与岸线都由 `center + lateral × N` 生成。

## 距离与最近点查询

样条参数不是等弧长参数。模型先用 1,024 段建立累计弧长表，再由目标距离二分定位相邻表项并恢复样条参数。B 的标记位置为：

```text
d(t) = d0 + speed × t
P(t) = center(d(t)) + lane × normal(d(t))
```

任意世界点先在 320 段粗表中寻找最近样本，再在相邻参数范围做 12 次局部细化。返回最近中心线点、切线、带符号横向距离、欧氏距离与 `inChannel`；河道内条件为到最近中心线的欧氏距离不大于半河宽。

开放河道不循环、不重生、不把越界标记夹回岸内。固定标记起点经过约束，保证 20 秒 B 时间线不会超过下游端点；超出开放域的距离查询会显式抛错。

## A / B 方向规则

```text
A: direction = (0, 1)
B: direction = tangent(closestCenterlinePoint(worldXZ))
speed(A) = speed(B) = 2.55
```

A 的标记从与 B 完全相同的初始世界位置出发，并沿 `+Z` 直移；B 沿中心线等弧长前进且保持初始横向车道。两侧不包含惯性、阻力或碰撞，所以结果只能解释为方向场的一致性差异。

## 指标

- 切线对齐均值与切线方向误差 P95。
- 河道内采样比例。
- 相对初始车道的 RMS 偏差。
- 沿河道切线的平均前进速度代理。
- 到中心线横向距离 P95 与河道外 marker-tick 数。
- 非有限值次数、配置哈希与结果摘要。
- 浏览器首帧、帧时间 P50/P95/最大值、长帧次数、draw calls、三角形、视口、质量档、控制台与请求错误。

`bankExitCount` 统计的是统计窗口内处于河道外的 marker-tick 数，不是“穿岸事件次数”；同一标记连续多个 tick 在河道外会被连续计数。

## 首轮通过条件

- 样条解析切线、连接连续性、正交标架、最近点往返、弧长重建、开放端点、中心线无自交、等弧长间距与岸线固定宽度检查通过。
- A/B 初始标记完全一致、速度模长相等，且只改变 `flowMode`。
- 同一配置重复运行的摘要一致，非有限值为 0。
- A 在弯道显示明确方向失配；B 切线对齐均值至少 `0.995`、方向误差 P95 不高于 `5°`、河道内比例至少 `0.995`。
- B 的河道内比例至少比 A 高 `0.15`，车道 RMS 偏差不高于 A 的 `35%`。
- 桌面临时门槛 P50 ≤ 22 ms；390px 移动档 P50 ≤ 33 ms。
- 桌面双视图、手机 A/B 切换、暂停、重置、reduced-motion 与 fallback 可用。
- 页面无横向溢出、未处理异常、控制台错误或失败请求。

浏览器 P95、最大帧时间和长帧次数作为尾部诊断公开记录，不通过丢弃长帧来美化结果。只有数值与真实浏览器检查共同通过，才可把 Gate 2 记为 `continue River visual baseline / hold shallow-water`。
