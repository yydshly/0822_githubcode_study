# 最小原型与验收规范

## 统一实验契约

每个模块都必须先回答一个场景问题，并遵守同一证据格式：

- A/B 使用相同相机、时长、设备、分辨率和随机种子。
- 一轮只改变一个主要变量；其他变化必须列为伴随变量。
- 记录实现版本、输入参数、质量档、帧时间、控制台错误和截图。
- 把“视觉观察”“运行测量”“模型推断”分开写。
- 页面同时提供能力说明、失败边界和降级路径。
- 原型通过不等于工程准确；真实性等级必须单独标记。

参考设备上的临时性能门槛为：桌面平衡档 P50 帧时间不高于 22 ms，390px 移动档 P50 不高于 33 ms；两者都要求页面无横向溢出、无未处理异常、可关闭运动。门槛必须随测试设备一起记录，不是跨设备承诺。

## 两级验证结构

从目标驱动阶段开始，证据分为两级：

1. **Capability Lab**：验证一个具体模型或表现层，继续使用单变量 A/B。
2. **Scenario Integration**：验证多个能力在同一宏观场景中的拓扑、单位、状态传递、因果关系、质量预算和性能。

集成页面可以包含多项能力，但每个外部输入和模块传递都必须可追踪。独立能力实验通过，不能代替集成通过；集成画面好看，也不能反向证明每个求解器正确。

每项能力和连接都必须标记真实性等级：`T0 Visual`、`T1 Kinematic`、`T2 Physically mapped`、`T3 Locally coupled` 或 `T4 Calibrated`。等级定义见 [`MACRO_GOAL.md`](MACRO_GOAL.md)。

## P0｜Local Liquid：已有基线

**场景问题**：局部水体能否对密度、容积、表面张力和刚体障碍产生可重复差异？

**现有实现**：Particles4All 五个使用场景、四个诊断入口、固定 solver-step 终点、区域探针和十条件硬件浏览器回归。

**保留角色**：作为局部自由液面、排水和刚体耦合模块，也作为后续海岸飞沫、河石扰动和瀑布落水池的候选局部效果；不扩张成海洋或整段河流求解器。

**下一门槛**：Apple/集成显卡兼容，移动端触控，复杂碰撞体接口，以及与统一 `sampleSurface` / `disturb` 契约的适配实验。

## P1｜Ocean MVP：开阔海面

**实现状态（2026-08-24）**：首轮固定协议已实现并通过数值、桌面、390px、reduced-motion、fallback 与三次隔离性能复测。Ocean 基线保留，FFT 因缺少高阶海况宿主需求而暂停；实现与原始数据见 [`ocean-mvp/`](ocean-mvp/README.md)。

**场景问题**：同一艘小型巡航艇在平静海况与有风涌浪中，能否呈现可重复、可解释的稳定性差异？

**最小实现**：

1. 以固定 6 组方向、波长、振幅和速度可控的 Gerstner 叠加波构造几何位移；总陡峭度必须受限，避免波面回环。
2. 用动态法线和分层细节表现近远尺度，不用局部粒子填满视野。
3. 让船体四个采样点通过同一波函数查询高度与法线，得到升沉、俯仰和横滚视觉代理，验证“看到的面”和“交互采样”一致。
4. 使用相机相对网格或分块重复隐藏边界，记录可见平铺和地平线破绽。

**单变量 A/B**：相同随机种子、船体、航向、速度、相机和 60 Hz 时间轴，A 为平静海况，B 只提高统一的海况/风浪输入；所有波参数由该输入和同一随机种子派生。后续再分别比较顺浪/横浪、4 波/8 波和 Gerstner/FFT，不与第一轮混在一起。

**首轮指标**：水面高度标准差、波峰高度 P95、坡度 P95、船体升沉 RMS、横滚/俯仰 RMS、非有限值、帧时间 P50/P95，以及输入与配置哈希。

**通过条件**：

- 固定镜头路线中不出现明显水面边界或静止接缝。
- 船体采样高度与渲染波函数来自同一参数源，无持续穿面或悬空；其姿态只是视觉浮力代理，不称为完整船舶水动力学。
- A/B 差异可由一个变量解释，截图和参数可复现。
- 同一配置重复运行的终点指标误差首版目标不超过 1%，B 的海面高度/坡度与船体姿态波动应稳定高于 A。
- 桌面、移动降级档达到统一实验契约；关闭反射后仍保留波形可读性。

**停止条件**：若需求只需要远景背景，则停在低成本着色水面；只有出现风谱、长距离海况、船舶路径或导演可控性需求时，才评估 FFT 波谱与更复杂 LOD。

## P2｜River MVP：沿地形流动

**实现状态（2026-08-24）**：固定数值协议、桌面、390px 正常/reduced-motion 与强制 WebGL fallback 均已通过；原始浏览器结果、截图与 Gate 状态见 [`river-mvp/EVIDENCE.md`](river-mvp/EVIDENCE.md)。实现采用固定样条和解析方向查询，不含浅水动力学。

**场景问题**：能否让河道形状、流向、岸线和漂浮物共同表达“水沿哪里、以何种节奏流动”？

**最小实现**：

1. 用 8 个固定控制点的 Catmull–Rom 中心线生成河道网格与两岸。
2. 用弧长查找表按距离采样中心线，并以最近点切线构成显式 `sampleFlow` 查询。
3. 让水面方向线索、诊断箭头和 8 个同起点漂浮标记读取同一 `flowMode`，检查视觉与对象运动是否矛盾。
4. 漂浮标记离开河道后不重生、不循环、不夹回岸内，避免隐藏固定方向在弯道中的累计误差。

**视觉原型单变量 A/B**：相同河道、宽度、速度模长、标记起点、种子、相机和时间轴，A 为世界 `+Z` 固定方向，B 只改为最近样条切线方向；检查弯道水纹、箭头与漂浮标记是否一致。该实验只证明视觉空间方向的一致性，不输出水位、流量或水动力结论。

**通过条件**：

- 固定样条切线、等弧长采样、最近点查询、开放端点与同起点检查通过，A/B 重放摘要一致且无非有限值。
- 河面视觉方向与漂浮标记的运动方向一致。
- 河宽、速度提示和质量档可配置，手机端不依赖高成本反射才能辨认河道。
- 页面明确标注 flow map 是视觉方向场，而不是测量流速。
- 桌面和 390px 达到统一临时 P50 门槛，并公开 P95、最大帧时间和长帧次数；reduced-motion 与 WebGL fallback 可用。

**升级门槛**：只有当场景需要闸门、堰、动态水深、回流或洪峰传播时，才建立局部/全段浅水高度场原型；仅仅需要“更快的水”不构成升级理由。

**浅水研究原型**：用二维网格保存床高 `B`、水深 `h` 和动量 `hu/hv`，采用固定步长、湿干边界与上游入流/下游开放边界。A 为原河道，B 只将一处河宽收窄约 30%；固定网格、步长、步数、来水和出口条件，比较测站水深、收窄区平均速度、出流量、湿单元和质量残差。首版目标包括无 NaN/Inf、非负水深、lake-at-rest 近似静止和质量残差可审计；实际阈值必须由运行结果校准。

## P3｜Waterfall MVP：落差与破碎

**实现状态（2026-08-24）**：固定模型 24 / 24 与 Chromium 硬件 WebGL2 的桌面、390px 正常/reduced-motion、强制 fallback 均通过。唯一因子是 `breakupMode`；A/B 的主水幕完全一致，白沫和雾在正式实验中关闭。能力 Gate 为 `continue Waterfall hybrid visual baseline`；Particles4All coupling 现由山地水系的 Pool 近景交互子目标决定是否进入。原始结果见 [`waterfall-mvp/EVIDENCE.md`](waterfall-mvp/EVIDENCE.md)。

**场景问题**：水幕、破碎、白沫和雾这四层中，哪些是瀑布可读性所必需，哪些只是昂贵装饰？

**最小实现**：

1. 由上游边缘生成主水幕/水柱网格，保证远景轮廓和连续来水。
2. 在边缘与撞击区发射有限粒子，表达分裂和飞溅。
3. 用泡沫带和深度衰减雾表达落水池冲击；每层均可独立关闭。
4. 首版通过 `WaterTransfer` 接收上游位置、方向、宽度和流量代理，并向下游输出落点、代表水量和扰动；只有近景碰撞子目标需要时才接入 Local Liquid。

**单变量 A/B**：A 只有主水幕，B 只增加破碎粒子层；相同曝光、相机和主水幕，判断粒子是否真正改善边缘、撞击点和尺度感。

**通过条件**：

- 远、中、近三个固定镜头都能读出起点、落差和撞击区。
- 粒子关闭后仍有连续水体；粒子开启后不出现发射器形状或突兀消失。
- 白沫和雾不遮蔽主要地形轮廓，移动档可以独立降低粒子与雾成本。
- 明确说明粒子是视觉采样，不据此计算真实流量。

**研究升级**：只有当上游浅水网格的出流被扣减、粒子携带对应质量/动量、落回下游后重新沉积并审计残差时，才可称“高度场—粒子质量交换”。否则即使画面连续，也只称视觉混合。

**首轮结果边界**：B 的固定活动代理均值为 69.6729，边缘扩展均值为 0.359470，落点占用均值为 0.357064；A 对应增量为 0。桌面与 390px 的细小错相碎滴增益可辨，移动端更克制。桌面 P50/P95 4.2/8.3 ms 与移动正常 4.2/4.3 ms 通过临时门；桌面/移动各一次 50.1/91.6 ms 长帧保留为优化项。这些都只证明视觉分层和整页总成本，不批准质量交换、粒子增量成本归因或落水池局部粒子求解。

## P4｜Flood Proxy：地形漫淹代理

**启动前提**：必须先有明确宿主场景，例如“围挡是否改变叙事中的传播路径”或“不同开口何时被水到达”。没有问题就不开发。

**最小实现**：

1. 使用低分辨率地形高度场和二维水深/速度网格。
2. 明确水源、边界、障碍、固定步长与数值稳定条件。
3. 将水深着色、到达时间和流向箭头作为诊断层，而不是只展示漂亮表面。
4. 保留网格分辨率、体积漂移和边界反射误差记录。

**单变量 A/B**：同一地形和来水，A 无围挡，B 只加入一段围挡；比较到达顺序、积水区域代理和质量漂移，不比较未经校准的真实米制水位。

**通过条件**：

- 固定输入下重复运行给出一致的到达顺序和区域趋势。
- 不出现非有限值、持续数值爆炸或无法解释的边界漏水。
- 展示网格分辨率与质量误差，并在页面醒目标记“概念/叙事代理”。
- 若要进入教育或决策产品，必须另设数据校准、专家审查和不确定性表达门。

Flood Proxy 与 Waterfall 可以共享地形高度场、固定步长和探针协议，但首版不强制共享求解器。若未来需要守恒的河流—陡坎—落水池连续系统，应先建立可审计的高度场流出，再开发粒子质量/动量转换；不能用视觉粒子补齐缺失的守恒证据。

## P5｜Watershed Integration Slice：山地水系集成切片

**实现状态（2026-08-24）**：`integration runtime evidence / T3 routing coupled`。公共单位、7 节点/6 连接拓扑、`WaterTransfer`、River 有限库存、Waterfall 固定延迟在途体积、有限容量 Pool、Floodplain 优先蓄水/障碍改道/边界和完整浏览器场景已运行；T2 模型 23 / 23、T3 模型 24 / 24、溢流模型 26 / 26、障碍路由模型 26 / 26，阈值与路径双 A/B 的桌面/390px/reduced-motion/fallback 检查通过。实现与边界见 [`watershed-slice/README.md`](watershed-slice/README.md)。

**宏观场景问题**：能否让同一个上游来水输入，连续驱动 River 出口、Waterfall 下落、Pool 水位和后续 Downstream/Flood 状态，并让观察者理解完整因果链？

**当前范围**：Source → River → Drop → Waterfall → 有限容量 Pool → Floodplain 优先蓄水格/障碍改道 → 固定开放边界。

**最小实现**：

1. 统一米、秒、体积流量、速度、落差和容量单位。
2. 用 `WaterGraph` 表达节点和连接，用 `WaterTransfer` 表达每步传递。
3. 适配现有 River 和 Waterfall，不重写其已验证表现基线。
4. 同一 `Q` 派生出口单位宽流量、水幕厚度代理、粒子代表量、飞行时间、撞击速度和 Pool 入流。
5. 粒子视觉数量与代表水量分离，使质量档只影响表现采样，不改变状态。
6. 页面公开输入、输出、存量、传输中水量和残差。

**单变量 A/B**：相同地形、水体拓扑、出口宽度、落差、种子、时长、相机和质量档，A/B 只改变 `dischargeScale`。所有 River、Waterfall 和 Pool 差异必须由该输入派生。

**首轮 `T2` 通过条件**：

- 世界单位、参数映射和适用假设完整公开。
- River 出口和 Waterfall 入口在位置、方向和有效宽度上连续。
- 落差与重力决定的飞行时间、落点和撞击速度通过模型测试。
- 高来水条件下的水幕、传递量、撞击和 Pool 入流按同一方向响应。
- 改变粒子视觉采样率不改变代表体积和 Pool 水位。
- 桌面、390px、reduced-motion 和 fallback 达到统一页面契约。

**T2 首轮结果**：A/B 固定输入差异仅为 `dischargeScale`。3/6 m³/s 来水形成 0.117/0.235 m 水幕厚度；落水时间 1.916 s、撞击速度 19.16 m/s。该轮证明映射一致，不证明上游扣减与延迟沉积。

**T3 结果**：A/B 均接收 40 m³ Source 输入，River 排出 60/120 m³并剩余 220/160 m³；在途体积 5.75/11.50 m³，累计沉积 54.25/108.50 m³，Pool 在固定出流后上升 0.010/0.139 m；全局残差低于 `2 × 10⁻¹⁰ m³`，最大单步残差为 0。瀑布的泡沫、涟漪和雾沫读取沉积状态，视觉质量不改变预算。

**T3 溢流结果**：容量固定为 1,710 m³。A 不溢流；B 在第 712 tick 首次溢流，最终累计溢流 28.50 m³、Floodplain 蓄水 26.4625 m³、固定边界流出 2.0375 m³并湿润 24/84 格。Pool、Floodplain 与全系统预算闭合，模型和视觉采样解耦。

**T3 障碍路由结果**：两组均使用高来水，唯一变量为 `floodplainRoutingMode`。开放路径与 8 格障碍路径的累计溢流、蓄水和边界输出相同；障碍路径平均横向距离从 5.60 m 增至 8.88 m，最远湿润行从第 3 行增至第 4 行，障碍格始终干燥。

**下一升级条件**：增加随时间变化的暴雨过程线或闸坝失效输入，公开到达时间曲线、峰值滞蓄和边界残差；只有静态优先路由无法回答传播速度或回水问题时才升级高度场/浅水方程。当前不称真实洪水传播，也不把内部代理用于工程预测。

完整执行计划见 [`MOUNTAIN_WATERSHED.md`](MOUNTAIN_WATERSHED.md)。

## 共用交付清单

每个 MVP 完成时至少交付：

- 一个无需构建即可由静态服务器运行的浏览器入口。
- 一组固定 A/B URL 或可序列化参数。
- 桌面和 390px 证据截图。
- 自动化或半自动化运行结果：帧时间、错误、输入与版本。
- `README`、`EVIDENCE`、真实性边界和来源列表。
- 明确的 `continue / hold / stop` 决策，而不是默认继续增加效果。

集成切片还必须交付：

- 场景配置、节点拓扑和公共单位；
- 模块适配器版本和传递契约；
- 输入、输出、存量和残差摘要；
- 固定远/中/近场景镜头；
- 宏观场景 Gate 结论，而不是只列出各模块通过情况。
