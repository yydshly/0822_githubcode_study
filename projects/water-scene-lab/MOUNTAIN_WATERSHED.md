# Mountain Watershed｜山地水系集成计划

## 计划目标

构建第一条可运行的连续水环境切片：水从上游水源进入弯曲河道，在断崖处转换为瀑布，落入水潭，再从水潭进入下游或洪泛区。它用于验证跨模块状态传递和因果关系，不用于真实流域预测。

```text
Source
  ↓ Q_in
River Reach
  ↓ Q_out, width, velocity
Waterfall Drop
  ↓ transferred volume, impact velocity
Pool
  ↓ level, overflow
Downstream / Floodplain
  ↓ Q_out
Sink
```

## 为什么它是第一条主线

- 当前 River 和 Waterfall 已有可运行能力，可以复用而不是推倒重来。
- Waterfall 正好暴露“粒子效果与实际流量没有映射”的关键问题。
- Flood Proxy 可以从“孤立候选”转为水潭溢流后的明确子目标。
- Particles4All 可以在落水池近景或刚体交互真正需要时接入。
- 同一场景能够同时检验地形、方向、落差、质量传递、视觉表现和性能分级。

## 用户可感知目标

第一条集成场景必须让观察者直接理解：

1. 水从哪里来、沿哪里走、在哪里下落、最后去哪里。
2. 上游来水增加时，河流出口、瀑布厚度/破碎、撞击和水潭变化共同响应。
3. 岩石、闸门或出口变化只在其应该影响的下游产生结果。
4. 远景能读懂完整水系，中景能读懂河流—瀑布转换，近景能读懂碰撞、泡沫和水滴。

## 第一阶段不重写什么

- 不重写 Ocean；该能力留给 Coastal World。
- 不立即把整条河替换成高成本求解器。
- 不立即把瀑布全部替换为 SPH/PBF 粒子。
- 不把视觉粒子一一当作真实水分子。
- 不为了目录整洁先迁移所有现有代码。

## 执行阶段

### W0｜目标与契约基线

**状态**：`completed as model contract`

产物：

- 宏观目标和真实性等级；
- `WorldContext`、`WaterGraph`、`WaterTransfer` 契约；
- 山地水系节点和端口配置；
- 能力证据与集成证据分离。

通过门：同一份场景配置能够明确列出节点、上下游、单位、真实性目标和缺失能力。

**结果**：`mountain-watershed-graph-v0` 已用 7 个节点和 6 条连接表达完整路径，并通过单位、拓扑、端口、传递、预算和错误输入检查。实现与结果见 [`watershed-slice/README.md`](watershed-slice/README.md)。

### W1｜Watershed Slice v0：共享参数驱动

**状态**：`completed / T2 runtime evidence passed`

最小场景：

- 一个固定山地地形；
- 一段 River 路径；
- 一个 Drop 节点；
- 一个 Waterfall 表现；
- 一个 Pool 水位代理；
- 一块诊断面板。

第一轮只要求 `T2 Physically mapped`：

- 世界单位使用米和秒；
- 输入体积流量 `Q`；
- `Q / outletWidth` 决定单位宽流量；
- 出口速度与有效截面决定水幕厚度代理；
- 落差和重力决定飞行时间、落点和撞击速度；
- 粒子发射率只是视觉采样率，但其代表水量与 `Q·dt` 绑定；
- 水潭水位代理读取累计入流和出流。

第一轮 A/B 只改变 `dischargeScale`：A 为低来水，B 为高来水；相机、地形、宽度、落差、种子、质量档和时长固定。所有可见变化必须由同一流量输入派生。

**结果**：连续浏览器场景已复用 River 等弧长路径，并建立抛物落水、水滴采样、Pool 水位和预算 HUD。模型 23 / 23，Chromium 桌面/390px/reduced-motion/fallback 功能检查通过；累计预算残差低于 `2 × 10⁻¹⁰ m³`。移动端 P95 含初始化与验证切换长帧，性能 Gate 保留为独立复测项。

### W2｜River → Waterfall 局部守恒

**状态**：`completed / T3 runtime evidence passed`

- 审计 River 出口每步流出量；
- 将对应体积转成瀑布传递包和有限视觉粒子；
- 粒子数量与物理代表量解耦；
- 记录上游扣减、传输中水量和残差。

通过门：固定输入下没有凭空增加水量；视觉质量档变化不改变代表的总水量。

**结果**：River 已使用有限库存并接收固定 Source 入流；每个 60 Hz 步进产生一个带体积、初速度、飞行时间和撞击速度的在途包。20 秒低/高来水分别排出 60/120 m³，最终在途 5.75/11.50 m³，质量档不参与预算。

### W3｜Waterfall → Pool 沉积与扰动

**状态**：`completed baseline / T3 state-driven rendering`

- 粒子或解析水束与地形/水潭碰撞；
- 计算落点、撞击速度和冲量代理；
- 将传递体积沉积到 Pool；
- 由撞击状态驱动白沫、飞沫、水雾和声音；
- 近景刚体交互使用按需加载的 Particles4All Local Physics Lens。

通过门：关闭泡沫和雾不会改变水潭质量状态；改变视觉粒子采样率不会改变水位。

**结果**：体积包达到 1.916 s 飞行时间后沉积到 Pool；20 秒累计沉积 54.25/108.50 m³，Pool 在固定出流后上升 0.010/0.139 m。连续水幕、在途水滴、撞击泡沫、涟漪和雾沫由同一状态驱动。后续 Waterfall Vertical Slice 已完成 Particles4All 按需近场镜头：宏观落差映射为有界 solver 输入，并由原库 PBF/Shape Matching 产生局部刚体响应。该接入当前属于桌面独立纵向样板，尚未并入 Watershed 全链质量预算。

### W4｜Pool → Downstream / Floodplain

**状态**：`active / capacity, priority-storage and barrier-routing baselines passed`

- 已实现 1,710 m³ Pool 容量和显式溢流；
- 已实现 12 × 7 确定性优先蓄水格与 0.25 m³/s 固定开放边界；
- 已记录首次溢流 tick、湿区、水深代理、蓄水量和全局/单步质量残差；
- 已完成开放路径/障碍改道 A/B：相同高来水和相同溢流体积下，8 个障碍格迫使湿润路径从两侧绕行；
- 当前推进暴雨过程线与闸坝失效时变输入，再决定低分辨率高度场或浅水方程是否进入。

这时 Flood Proxy 不再是无宿主的独立 Demo，而是山地水系中的明确子目标。

**当前结果**：固定 20 秒 A/B 中，A 不溢流；B 在第 712 tick 首次越过容量，累计溢流 28.50 m³，Floodplain 蓄水 26.4625 m³、边界流出 2.0375 m³并湿润 24/84 格。溢流模型 26/26、桌面/移动/reduced-motion/fallback 通过。该结果是优先蓄水代理，不是浅水传播或真实洪水预测。

**障碍结果**：开放/障碍两组的 River、Waterfall、Pool、累计溢流、Floodplain 蓄水和边界输出完全相同。障碍组中央 8 格保持干燥，平均横向距离由 5.60 m 增至 8.88 m，最远湿润行由第 3 行增至第 4 行；路由模型 26/26、桌面/移动通过。该结果只证明障碍感知的确定性优先路由，不证明流速、压力、回水或浅水动量。

## 集成证据指标

| 维度 | 首轮指标 |
| --- | --- |
| 拓扑 | 节点数、连接数、无断开的必需端口 |
| 单位 | 米、秒、体积流量、速度和容量定义完整 |
| 因果 | `Q` 变化后 River、Waterfall、Pool 的响应方向一致 |
| 连续性 | 上游出口位置/方向与瀑布入口一致，瀑布落点在 Pool 有效域内 |
| 质量 | 每步输入、输出、存量、传输中水量与残差 |
| 表现 | 远、中、近固定镜头可读；表现层不改变质量状态 |
| 性能 | 桌面/移动 P50、P95、最大帧时间和长帧数 |
| 证据 | 配置哈希、固定步数、随机种子、截图和浏览器环境 |
