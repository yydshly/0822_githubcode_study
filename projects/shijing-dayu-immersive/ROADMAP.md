# 产品化扩展路线

当前版本已经足够用于演示和方向验证，建议先冻结功能，通过真实用户观察决定下一轮，不继续无目标堆叠控件。

## 已完成：可演示闭环

- 多书展厅、按章阅读、段落选择与左右图文同步；
- 简明讲解、沉浸故事、史料导读三种内容模式；
- MiniMax 音频、系统语音降级、自动续段/续章和朗读定时；
- 阅读恢复、最近历史、每日计划和移动端听读；
- Book Schema 1.0 与 JSON/TXT/Markdown 本地导入；
- GitHub Pages 纯静态部署。

## 下一阶段：优先改善使用体感

仅在用户测试证明有需要后实施：

1. 导入预览：确认书名、章节树、段落数和预计时长后再入库。
2. 章节校正：允许合并、拆分和改名，避免文本解析错误直接污染书架。
3. 移动连续性：横竖屏或断点变化后重新提示当前朗读段，并把触控热区扩展到 44px。
4. 句子级跟读：在不恢复大型播放器的前提下，增加轻量句子高亮、句子跳转和本段剩余时间。
5. 媒体预取：提前加载下一段音频和场景，降低段落切换等待。

## 内容生产能力

建立独立、可重试的加工流水线，而不是把生成逻辑塞进阅读器：

```text
原始文章
  → 章节/段落解析
  → 白话讲解、故事模式、史料导读
  → 人工审校与来源确认
  → MiniMax TTS
  → 图片/视频场景生成
  → Book JSON 发布
```

每一步应保存版本、状态、错误和成本；内容编辑可以只重跑某一段或某一种模式。

## 正式产品基础设施

- 账号与跨设备同步，同时保留离线阅读；
- 对象存储/CDN、媒体转码和缓存；
- 内容管理后台、版本发布、回滚和专业审校；
- 搜索、标签、收藏和书架排序（书籍数量达到一定规模后再加入）；
- 使用行为与播放失败监控；
- 数据导出、删除和隐私说明；
- 版权、引用、AI生成内容和未成年人使用边界。

## 验证指标

产品化阶段优先观察：

- 用户能否在 30 秒内找到书并开始阅读/听读；
- 播放中主动选段是否总能接管；
- 一章完成率与第二天继续率；
- 导入后章节识别正确率和用户修正次数；
- TTS、图片及视频资源失败率；
- 手机端误触、回到当前段和横竖屏中断情况。

这些数据比继续增加视觉效果更能决定产品下一步。
