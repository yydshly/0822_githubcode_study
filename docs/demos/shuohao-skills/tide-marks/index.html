库探索成功，短剧投产尝试失败

shuohao-skills 成功把已有小说组织成结构化短剧资料，但没有保证小说原型、因果推进和改编后的行动连续性。《潮痕》的两个连续视频样本已经触发停止条件，因此不再扩大生成。

这个库究竟能做什么

已有小说→大纲→角色→美术→剧本→分镜与模型输入

它用 Skills 规定每个阶段的输出契约，再用零依赖 Node.js 脚本校验字段、ID、上下游引用、时长和切点。大模型负责实际内容判断，图像/视频模型负责媒体结果。

已验证的价值

结构化、可追踪、可重复导出；能抓格式、引用、时长和切点错误；适合作为多模型协作的中间规格。

没有覆盖的能力

小说质量、人物欲望、全剧因果、短剧改编取舍、跨段动态连续性、视频生成、返工闭环和最终剪辑。

研究过程

阶段研究内容结果
1. 上游复现固定提交，运行五模块及合成报告自测，复现《渡口》夹具。确定性管线可运行，1,262 项自测通过。
2. 原创盲测使用原创《潮痕》生成 6 集大纲、角色、美术、剧本、59 段和 193 镜。证明工作流可以约束新任务，而不只展示自带 JSON。
3. 生产扩展生成参考图、逐镜图、提示词、上传顺序、字幕、声音表和剪辑资料。文件齐全，但文件数量不能代表故事质量。
4. 事后审计增加 11 项故事逻辑修复和 58 个段间边界审计。暴露原库没有小说因果和跨段状态质量门。
5. 视频小样生成 E01-01、E01-02 两个连续样本。人物从“奔向门”回退为“返回开盒”，行动和空间因果断裂。
6. 停止决策判断是否继续生成剩余视频。停止。上游叙事门未通过，继续生成只会扩大返工。

失败证据如何理解

两个样本证明了什么

它们不能证明 59 段每一段都会失败，但足以证明当前流程缺少投产前叙事质量门。原库 validate 通过只表示规格合法；图片齐全也不表示动态因果成立。

早期静态演示

这是由关键帧按时间线组装的无声 animatic，只能展示图片顺序和节奏，不是 H3 生成视频，也不能证明真实动作能够连续。

最终研究结论

这次研究不再继续深入。成果不是完成一部短剧，而是确认：结构化拆分工具可以提高资料组织和机械校验能力，但不能替代小说质量、全剧因果和真正的短剧改编。后续若重启，应先补齐小说原型评审、因果图、状态时间线与连续场景走查，再只生成 2～3 个视频小样验证。
